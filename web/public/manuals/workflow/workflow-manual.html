About this manual

The workflow engine moves work between people. Each workflow is a diagram of steps; each human step becomes a task in someone's inbox. When the task is done, the workflow moves to the next step on its own. The engine also keeps a full history: who did what, when, and with what decision.

Note

Everything in sections 4 to 6 and 8 to 9 was added on top of the existing engine. A workflow that does not use versions, data fields, documents or out of office runs exactly as before.

Key ideas

IdeaWhat it means
WorkflowA diagram of steps (BPMN) with a code, e.g. DISBURSEMENT_REQUEST_WF. Only a released, active workflow can start.
Workflow typeSystem-built: started by the system (factoring, portfolios, disbursements). User-defined: started by a user from Start a request, on one document (vacation, expense claim).
InstanceOne run of a workflow for one business record (a disbursement, a claim). It carries its own data and history.
StepA box in the diagram. A human step creates a task; a system step or a decision runs on its own.
TaskThe work waiting at a human step, shown in the inbox of a role or one user.
ClaimTaking a task so that it is yours. A role task is visible to everyone in the role until someone claims it.
OutcomeHow a task ended: APPROVE, REJECT, RETURN, COMPLETE… The arrow with the same name decides the next step.
Business screenA Capitra page a step opens (its Route), such as Treasury Disburse. The task is completed from that page.
VersionA frozen copy of a released workflow. Running instances keep their version when the workflow changes.
Data fieldA value each instance carries (amount, client, decision), with a type that is checked.
DocumentA form designed once in the Document Designer, with its own fields and which of them are required. A user-defined workflow links one document to the whole workflow; a system-built workflow can link a document to any step.
RequestOne run of a user-defined workflow, sent by a user on its document. The requester follows it under My requests.
Data sourceA list of values a form's drop-down offers: users, clients, currencies, or a list you keep.
Out of officeWho works your tasks while you are away, between two dates.
3

Designing a workflow

Workspace → Workflow Registry lists every workflow with its code, version, status and whether it is active. Open one to edit it in the designer, or use New workflow.

The designer

Drag elements from Tools onto the canvas and connect them with arrows. Click an element to open its Properties on the right; click the empty canvas for the Workflow Properties. The header holds Fit, Versions (section 4), Data Fields (section 5), BPMN XML and Save Workflow.

Workflow type

In Workflow Properties, under Workflow Type, choose who starts the workflow:

TypeStarted byDocuments
System-builtThe system, from its module (factoring, portfolios, disbursements). Never offered on Start a request.Optional, on any human step (step setting Document).
User-definedA user, from Start a request (section 8).Exactly one, for the whole workflow, chosen under Document in Workflow Properties. The requester fills it in; every approval step shows it read-only.
Remember

A user-defined workflow can be saved as a Draft without a document, but it is released only once its document is chosen. Workflows made before types count as user-defined when their Start had a form, and system-built otherwise.

Step settings

SettingWhat it does
Step CodeA stable code such as TREASURY_DISBURSE. Modules recognise steps by it, so keep it once in use.
Step NameWhat people see in the inbox.
Step TypeHumanTask (creates a task), SystemTask, Decision, Start, End.
AssignmentRole (everyone in the role sees it) or User (one person, by user name in Assignee).
Product Event RuleThe product rule posted when the step completes: its charges and GL entries.
DocumentSystem-built workflows only: the document people work on at this step (section 6). In a user-defined workflow every step shows the workflow's document.
Route / PageThe business screen the task opens, with its parameters. Leave empty for a step worked on its form.
ActionsThe buttons that complete the task: APPROVE, REJECT, RETURN, COMPLETE… CLAIM is the claim button, not an outcome.

Arrows and outcomes

When a step has more than one arrow out, name each arrow after an outcome (APPROVE, REJECT). The task's outcome picks the arrow. With one arrow, any outcome follows it.

Saving and releasing

  1. Set Status to Released and leave Active on, so the workflow can start.
  2. Save Workflow. If the steps or arrows changed, Capitra makes a new version (section 4).
  3. A Draft workflow can be saved as often as you like; it cannot start.
4

Versions

Each time a released workflow is saved with changed steps or arrows, Capitra keeps the old one as a version and the change becomes the new current version. Instances already running stay on the version they started with, so a change never breaks work in progress. Moving boxes around (layout only) does not make a new version.

  • View opens an old version read-only. A banner says so; Back to current workflow returns.
  • Save is off while you look at an old version.
  • The version number is set by Capitra and shown in the chip beside the code.

Data fields

Data fields are the values each instance of a workflow carries: the amount, the client, the decision. Open them with Data Fields in the designer. Each field has a name (what screens and forms use, keep it once in use), a label, a type, whether it is required, a default and, for Choice, its choices.

Documents and data sources

A document is a form you design once in the Document Designer: its own fields, which of them are required, and how it looks. It does not belong to any workflow. Workflows link it in the designer: a user-defined workflow on the whole workflow, a system-built workflow on a step (section 3).

Designing a document

  1. Workspace → Document Designer → New document. Give it a name and a code, e.g. VACATION_REQUEST.
  2. Under Fields, Add field for each value: its label (the name fills in by itself), its type, the choices of a Choice list, a default, and whether it is Required.
  3. Each field appears under Layout. Click one to set its label on the form, its control, its data source (for a drop-down), its width on a 2-column document, help text, and Read-only. Add Headings and Notes between fields, and order them with the arrows.
  4. The Preview shows the document as people will see it.
  5. Create document. Used by shows the workflows that link it.

Data sources

Workspace → Data Sources. The lists a document's drop-downs offer. Three are built in and always current: Users, Clients and Currencies. Make your own for anything else: a code, a name and items, each with the value that is stored and the label people see.

Remember

A document in use cannot be deleted, and its code cannot change; switch it off instead. A form made before documents shows older form of its workflow: open it and save it once to make it a document of its own; the workflow keeps using it.

7

Working your tasks

My Inbox lists the tasks you may work: those assigned to you, to one of your roles, the ones you claimed, and those of people you cover (section 9). Overdue tasks come first. Filter by All, Claimed by me, Unclaimed or Overdue, search, or pick a workflow.

The steps of a task

1
Claim. The task becomes yours; others in the role no longer see it.
Claimed
2
Start work. Opens the business screen, or opens the step's form for filling in. Continue work returns to the screen later.
In progress
3
Complete. On the business screen, or with the action buttons under the form (Approve, Reject…). Add an optional comment.
Completed

A step worked on its form

After Start work the form opens for filling in. Required fields carry an orange star. If one is empty, the task is not completed: the message says which field, and what you typed stays on the page. Rejecting or returning a task does not need the form filled in.

Approving a request

A task of a user-defined workflow shows the request as the requester sent it, marked The request as sent: read-only. Read it, add a comment, then Approve or Reject. The requester sees your decision and comment under My requests (section 8).

8

Start a request

Anyone can send a request (a vacation, an expense claim…) with Start a request on Home, or Workspace → Start a request. The page lists the user-defined workflows only; system-built workflows are started by their modules.

  1. Choose the request on the left.
  2. Enter a business reference if you have one.
  3. Fill in the document. Defaults are already there; required fields carry an orange star.
  4. Send request. The message says which step comes next and who has it.

My requests

Under the form, My requests lists what you sent, newest first: In progress with the step it is waiting at, or Approved / Rejected with who decided, when, and their comment.

9

Out of office

Workspace → Out of Office, or the button on My Inbox. Choose who works your tasks, for all workflows or one, and the first and last day away. While the dates run:

  • New tasks meant for you go to your delegate.
  • Your delegate also sees the tasks already waiting for you and for your roles, with a For <you> tag, and a banner says whom they cover.
  • A task you had claimed shows Take over: the delegate claims it from you.
  • A rule for one workflow wins over the rule for all workflows. If your delegate is away too, the task passes to their delegate (up to five steps, never back to you).
Tip

Switch an entry Off to keep it for next time without using it. Workflow administrators can choose Everyone to see and set entries for other people.

عن هذا الدليل

محرك سير العمل ينقل العمل بين الأشخاص. كل سير عمل مخطط من الخطوات، وكل خطوة بشرية تصبح مهمة في صندوق مهام شخص ما. وعند إنجاز المهمة ينتقل سير العمل إلى الخطوة التالية تلقائيًا، ويحتفظ المحرك بسجل كامل: من فعل ماذا ومتى وبأي قرار.

الصفحةمكانهامن يستخدمها
صندوق مهاميزر صندوق المهام في الشريط العلوي، أو مساحة العمل ← صندوق مهاميكل من ينجز المهام
تقديم طلبزر تقديم طلب في الصفحة الرئيسية، أو مساحة العمل ← تقديم طلبالجميع: إرسال طلب (إجازة، مصروفات…) ومتابعته في طلباتي
الغياب عن العملمساحة العمل ← الغياب عن العمل، أو الزر في صندوق المهامالجميع، ويمكن للمسؤولين تسجيله لغيرهم
محرك سير العملمساحة العمل ← محرك سير العملالمسؤولون: المهام الجارية وزمن إنجازها
سجل مسارات العمل والمصمممساحة العمل ← سجل مسارات العملمسؤولو سير العمل
مصمم المستندات ومصادر البياناتمساحة العمل ← مصمم المستندات / مصادر البياناتمسؤولو سير العمل

كل ما في الأقسام من ٤ إلى ٦ ومن ٨ إلى ٩ أُضيف فوق المحرك القائم. سير العمل الذي لا يستخدم الإصدارات أو حقول البيانات أو المستندات أو الغياب يعمل كما كان تمامًا.

مفاهيم أساسية

المفهوممعناه
سير العملمخطط خطوات (BPMN) له رمز، مثل DISBURSEMENT_REQUEST_WF. لا يبدأ إلا سير عمل منشور ومفعّل.
نوع سير العملمبني في النظام: يبدؤه النظام (التخصيم، المحافظ، الصرف). معرّف من المستخدم: يبدؤه المستخدم من تقديم طلب على مستند واحد (إجازة، مطالبة مصروفات).
النسخة الجاريةتشغيل واحد لسير العمل لسجل عمل واحد (صرف، مطالبة)، ولها بياناتها وسجلها.
الخطوةمربع في المخطط. الخطوة البشرية تنشئ مهمة، وخطوة النظام أو القرار تعمل تلقائيًا.
المهمةالعمل المنتظر عند خطوة بشرية، ويظهر في صندوق مهام دور أو مستخدم واحد.
الاستلامأخذ المهمة لتصبح لك. مهمة الدور يراها كل أفراد الدور حتى يستلمها أحدهم.
النتيجةكيف انتهت المهمة: اعتماد، رفض، إرجاع، إكمال… والسهم الذي يحمل الاسم نفسه يحدد الخطوة التالية.
شاشة العملصفحة في كابيترا تفتحها الخطوة (المسار)، مثل صرف الخزينة، وتُكمل المهمة منها.
الإصدارنسخة مجمّدة من سير عمل منشور. النسخ الجارية تبقى على إصدارها عند تغيير سير العمل.
حقل البياناتقيمة تحملها كل نسخة (المبلغ، العميل، القرار) بنوع يتم التحقق منه.
المستندنموذج يُصمَّم مرة واحدة في مصمم المستندات، بحقوله الخاصة وأيها إلزامي. سير العمل المعرّف من المستخدم يربط مستندًا واحدًا بسير العمل كله، وسير العمل المبني في النظام يمكنه ربط مستند بأي خطوة.
الطلبتشغيل واحد لسير عمل معرّف من المستخدم، يرسله المستخدم على مستنده ويتابعه في طلباتي.
مصدر البياناتقائمة قيم تعرضها القائمة المنسدلة في النموذج: المستخدمون أو العملاء أو العملات أو قائمة تحتفظ بها.
الغياب عن العملمن ينجز مهامك أثناء غيابك بين تاريخين.

تصميم سير العمل

مساحة العمل ← سجل مسارات العمل يعرض كل مسارات العمل برمزها وإصدارها وحالتها وتفعيلها. افتح أحدها لتعديله في المصمم، أو استخدم سير عمل جديد.

المصمم

اسحب العناصر من الأدوات إلى لوحة الرسم وصِل بينها بالأسهم. اضغط على عنصر لفتح خصائصه على الجانب، واضغط على مساحة فارغة لفتح خصائص سير العمل. في أعلى الصفحة: ملاءمة، الإصدارات (القسم ٤)، حقول البيانات (القسم ٥)، BPMN XML وحفظ سير العمل.

نوع سير العمل

في خصائص سير العمل تحت نوع سير العمل اختر من يبدأ سير العمل:

النوعيبدؤهالمستندات
مبني في النظامالنظام من وحدته (التخصيم، المحافظ، الصرف). لا يظهر في تقديم طلب.اختياري على أي خطوة بشرية (إعداد المستند في الخطوة).
معرّف من المستخدمالمستخدم من تقديم طلب (القسم ٨).مستند واحد لسير العمل كله، يُختار تحت المستند في خصائص سير العمل. يملؤه مقدم الطلب، وتعرضه كل خطوات الاعتماد للقراءة فقط.
تذكّر

يمكن حفظ سير العمل المعرّف من المستخدم كمسودة بلا مستند، لكنه لا يُنشر إلا بعد اختيار مستنده. مسارات العمل المنشأة قبل الأنواع تُعد معرّفة من المستخدم إذا كان لحدث بدايتها نموذج، ومبنية في النظام في غير ذلك.

الإسناددور (يراها كل أفراد الدور) أو مستخدم (شخص واحد باسم المستخدم في خانة المسند إليه).
قاعدة حدث المنتجقاعدة المنتج التي تُرحَّل عند إكمال الخطوة: رسومها وقيودها المحاسبية.
المستندلمسارات العمل المبنية في النظام فقط: المستند الذي يُعمل عليه في هذه الخطوة (القسم ٦). في سير العمل المعرّف من المستخدم تعرض كل خطوة مستند سير العمل.
المسار / الصفحةشاشة العمل التي تفتحها المهمة ومعاملاتها. اتركه فارغًا لخطوة تُنجز على نموذجها.
الإجراءاتالأزرار التي تُكمل المهمة: اعتماد، رفض، إرجاع، إكمال… أما الاستلام فهو زر الاستلام وليس نتيجة.

الأسهم والنتائج

إذا خرج من الخطوة أكثر من سهم، فسمِّ كل سهم باسم نتيجة (APPROVE، REJECT)، ونتيجة المهمة تختار السهم. ومع سهم واحد تتبعه أي نتيجة.

الحفظ والنشر

  1. اجعل الحالة منشور واترك مفعّل مشغّلًا ليمكن بدء سير العمل.
  2. حفظ سير العمل. إذا تغيّرت الخطوات أو الأسهم ينشئ كابيترا إصدارًا جديدًا (القسم ٤).
  3. يمكن حفظ سير العمل المسودة متى شئت، لكنه لا يبدأ.
٤

الإصدارات

في كل مرة يُحفظ فيها سير عمل منشور بخطوات أو أسهم متغيرة، يحتفظ كابيترا بالقديم كإصدار، ويصبح التعديل هو الإصدار الحالي. النسخ الجارية تبقى على الإصدار الذي بدأت به، فلا يكسر التعديل عملًا قائمًا. تحريك المربعات فقط (الشكل) لا ينشئ إصدارًا جديدًا.

  • عرض يفتح إصدارًا قديمًا للقراءة فقط مع شريط يوضح ذلك، والرجوع إلى سير العمل الحالي يعيدك.
  • الحفظ متوقف أثناء عرض إصدار قديم.
  • رقم الإصدار يحدده كابيترا ويظهر في الشارة بجوار الرمز.
٥

حقول البيانات

حقول البيانات هي القيم التي تحملها كل نسخة من سير العمل: المبلغ والعميل والقرار. افتحها من حقول البيانات في المصمم. لكل حقل اسم (تستخدمه الشاشات والنماذج، فلا تغيّره بعد الاستخدام)، وعنوان، ونوع، وهل هو إلزامي، وقيمة افتراضية، وخيارات لنوع الاختيار.

المستندات ومصادر البيانات

المستند نموذج تصممه مرة واحدة في مصمم المستندات: حقوله الخاصة، وأيها إلزامي، وشكله. لا ينتمي المستند إلى سير عمل بعينه، بل تربطه مسارات العمل في المصمم: سير العمل المعرّف من المستخدم على مستوى سير العمل كله، والمبني في النظام على خطوة (القسم ٣).

تصميم مستند

  1. مساحة العمل ← مصمم المستندات ← مستند جديد. أعطه اسمًا ورمزًا، مثل VACATION_REQUEST.
  2. تحت الحقول اضغط إضافة حقل لكل قيمة: عنوانها (يُملأ الاسم تلقائيًا)، ونوعها، وخيارات قائمة الاختيار، وقيمة افتراضية، وهل هو إلزامي.
  3. يظهر كل حقل تحت التخطيط. اضغط عليه لضبط عنوانه في المستند وأداته ومصدر بياناته (للقائمة المنسدلة) وعرضه في مستند من عمودين ونص المساعدة وللقراءة فقط. أضف عناوين وملاحظات بين الحقول ورتّبها بالأسهم.
  4. المعاينة تعرض المستند كما سيراه المستخدمون.
  5. إنشاء المستند. خانة مستخدم في تعرض مسارات العمل التي تربطه.

مصادر البيانات

مساحة العمل ← مصادر البيانات: القوائم التي تعرضها القوائم المنسدلة في المستندات. ثلاثة منها مدمجة ومحدّثة دائمًا: المستخدمون والعملاء والعملات. وأنشئ قائمتك لأي شيء آخر: رمز واسم وعناصر، لكل عنصر قيمة تُخزَّن وعنوان يراه المستخدم.

تذكّر

لا يمكن حذف مستند مستخدم ولا تغيير رمزه؛ أوقفه بدلًا من ذلك. النموذج المنشأ قبل المستندات يظهر عليه older form of مع اسم سير عمله: افتحه واحفظه مرة واحدة ليصبح مستندًا مستقلًا، ويستمر سير العمل في استخدامه.

٧

إنجاز مهامك

صندوق مهامي يعرض المهام التي يمكنك إنجازها: المسندة إليك أو إلى أحد أدوارك، وما استلمته، ومهام من تنوب عنهم (القسم ٩). المتأخرة أولًا. صفِّ حسب الكل أو المستلمة مني أو غير المستلمة أو المتأخرة، أو ابحث، أو اختر سير عمل.

مراحل المهمة

١

مستلمة

مكتملة

خطوة تُنجز على نموذجها

بعد بدء العمل يُفتح النموذج للتعبئة. الحقول الإلزامية عليها نجمة برتقالية، وإذا كان أحدها فارغًا لا تكتمل المهمة: الرسالة تحدد الحقل، ويبقى ما كتبته في الصفحة. رفض المهمة أو إرجاعها لا يحتاج إلى تعبئة النموذج.

اعتماد طلب

مهمة سير العمل المعرّف من المستخدم تعرض الطلب كما أرسله مقدمه، وعليه The request as sent: read-only. اقرأه وأضف تعليقًا ثم اعتماد أو رفض. يرى مقدم الطلب قرارك وتعليقك في طلباتي (القسم ٨).

٨

تقديم طلب

يمكن لأي مستخدم إرسال طلب (إجازة، مطالبة مصروفات…) بزر تقديم طلب في الصفحة الرئيسية، أو مساحة العمل ← تقديم طلب. تعرض الصفحة مسارات العمل المعرّفة من المستخدم فقط؛ أما المبنية في النظام فتبدؤها وحداتها.

  1. اختر الطلب من القائمة.
  2. أدخل مرجع العمل إن وُجد.
  3. املأ المستند؛ القيم الافتراضية موجودة مسبقًا، والحقول الإلزامية عليها نجمة برتقالية.
  4. إرسال الطلب. الرسالة تحدد الخطوة التالية ومن لديه المهمة.

طلباتي

أسفل النموذج تعرض طلباتي ما أرسلته، الأحدث أولًا: قيد التنفيذ مع الخطوة التي ينتظر عندها، أو معتمد / مرفوض مع من قرر ومتى وتعليقه.

٩

الغياب عن العمل

مساحة العمل ← الغياب عن العمل، أو الزر في صندوق المهام. اختر من ينجز مهامك، لكل مسارات العمل أو لواحد منها، وأول وآخر يوم غياب. أثناء هذه الفترة:

  • المهام الجديدة الموجهة إليك تذهب إلى من ينوب عنك.
  • يرى من ينوب عنك أيضًا المهام المنتظرة لك ولأدوارك، عليها وسم نيابة عن…، وشريط يوضح عمّن ينوب.
  • المهمة التي كنت قد استلمتها يظهر عليها تولّي المهمة فيستلمها النائب منك.
  • قاعدة سير العمل الواحد تسبق قاعدة كل مسارات العمل. وإذا كان النائب غائبًا أيضًا تنتقل المهمة إلى نائبه (حتى خمس خطوات، ولا تعود إليك).
نصيحة

أوقف السجل لتحتفظ به للمرة القادمة دون استخدامه. ويمكن لمسؤولي سير العمل اختيار الجميع لرؤية سجلات غيرهم وتسجيلها.
